# Lift Recorder v1 — Shared Spec (the contract every component builds against)

Goal of v1: **start a session on the watch, walk to the bar, lift, drop it, and the iPhone
shows that lift's bar path a few seconds later. Only the lifts are kept, not the walking in
between.** Plus a debug mode that records the whole session, so the detector can be tuned
on real data.

Units everywhere: seconds, meters, m/s, m/s². Raw sensor values stay in CoreMotion units
(g for acceleration, rad/s for rotation rate). `G = 9.80665`.

## 2. Data format: `LiftRecording` (JSON, columnar)

One file per lift, `<id>.json`. Columnar arrays keep it compact and trivial to load in Python.

```json
{
  "version": 1,
  "id": "UUID",
  "sessionId": "UUID",
  "index": 3,                       // 1-based lift number within the session
  "kind": "lift",                   // "lift" only in v1 (debug sessions use CSV, §2.1)
  "liftType": "snatch",             // LiftType raw value (§3)
  "loadKg": null,                   // optional
  "startDate": "2026-10-25T18:03:11.250Z",   // ISO8601 wall clock of motion.t == 0
  "homingTime": 2.0,                // watch's online estimate, seconds on motion.t axis (nullable)
  "endTime": 7.4,                   // nullable
  "endReason": "drop",              // EndReason raw value (nullable)
  "motion": {                       // CMDeviceMotion @ 200 Hz (CMBatchedSensorManager)
    "t":  [..],                     // seconds, relative to first motion sample (starts at 0)
    "qw": [..], "qx": [..], "qy": [..], "qz": [..],   // attitude.quaternion
    "ax": [..], "ay": [..], "az": [..],               // userAcceleration (g)
    "gx": [..], "gy": [..], "gz": [..],               // gravity (g)
    "rx": [..], "ry": [..], "rz": [..]                // rotationRate (rad/s)
  },
  "accel": {                        // raw accelerometer @ 800 Hz (g, includes gravity)
    "t": [..], "x": [..], "y": [..], "z": [..]        // same time base as motion.t
  }
}
```

- All arrays inside `motion` have equal length; same for `accel`. `accel` may be empty.
- Time base: CoreMotion timestamps are seconds since boot. Snippet time 0 = first motion
  sample of the snippet; `accel.t` uses the same offset (may start slightly negative or
  positive, that's fine).
- `startDate` = boot date + first motion timestamp, where
  `bootDate = Date() - ProcessInfo.processInfo.systemUptime`.
- JSON dates: ISO8601 (`JSONEncoder.DateEncodingStrategy.iso8601`).

### 2.1 Debug full-session recording (CSV)

When "Record full session (debug)" is on, the watch also appends **every** device-motion
sample to `session-<sessionId>.csv` (written incrementally per batch, never held in memory):

```
# barpath-session v1, sessionId=<UUID>, startDate=<ISO8601>, liftType=<raw>
t,qw,qx,qy,qz,ax,ay,az,gx,gy,gz,rx,ry,rz
0.000000,...
```
Six decimals for t, five for the rest. Sent to the phone at session end via `transferFile`.
No 800 Hz accel in the CSV (keeps size ≈ 20 MB per 10 min).

## 4. Online lift detector (runs live on the watch; coarse but robust)

Purpose: find *homing* (lifter set, wrist still, just before the pull) and *end* (bar held
still after the lift, right before it's dropped) well enough to cut a snippet with margins.
The phone re-detects precisely (§5). Python (`tools/barpath/detector.py`) and Swift implement
**the same logic with the same defaults**.

Per sample (in order), with `dt = clamp(t - tPrev, 0, 0.05)` (first sample dt = 0):

```
ghat     = gravity.normalized
aUp      = +(userAccel · ghat) * G                      // m/s², + = up (see sign note below)
rotEMA  += α (|rotationRate| - rotEMA)                  // α = min(1, dt / emaTau)
accEMA  += α (|userAccel|   - accEMA)                   // g
isStill  = rotEMA < stillRot && accEMA < stillAcc
stillDur = isStill ? stillDur + dt : 0
armVertical = |ghat.x| >= armVerticalMin                // forearm roughly vertical
```

| Config field | Default | Meaning |
|---|---|---|
| `emaTau` | 0.08 s | smoothing for stillness |
| `stillRot` | 0.5 rad/s | |
| `stillAcc` | 0.06 g | |
| `armMinStill` | 0.3 s | stillness needed to arm |
| `armVerticalMin` | 0.7 | |ghat.x| threshold |
| `rehomeStill` | 0.15 s | stillness that re-homes while armed |
| `startVelocity` | 0.5 m/s | upward velocity that confirms a pull |
| `startWindow` | 1.0 s | max motion time after homing to reach startVelocity |
| `anchorStill` | 0.3 s | stillness that counts as a zero-velocity anchor in a lift |
| `dropDistance` | 0.5 m | fall below the last anchor height ⇒ dropped |
| `returnHeight` | 0.15 m | |h| below this while still ⇒ bar returned to start |
| `returnStill` | 0.5 s | |
| `noAnchorTimeout` | 4.0 s | lift with no anchor at all ⇒ end (missed lift) |
| `maxLiftDuration` | 15.0 s | hard cap |
| `cooldown` | 1.5 s | ignore input after an end |

States:

- **idle**: if `stillDur ≥ armMinStill && armVertical` → `armed`, `homingTime = t`, emit `.armed(homingTime)`.
- **armed**:
  - if `stillDur ≥ rehomeStill`: `homingTime = t`, `v = 0`, `motionTime = 0`; if `!armVertical` → `idle`, emit `.disarmed`.
  - else (moving): `v += aUp*dt`, `motionTime += dt`.
    - `v ≥ startVelocity` → `lifting`, emit `.liftStarted(homingTime)`. Init lift vars: `h = 0`
      (then integrate this sample's v), `maxH = 0`, `hadAnchor = false`, `liftStart = homingTime`.
    - else if `motionTime > startWindow` → `idle`, emit `.disarmed`.
- **lifting** (each sample): `v += aUp*dt`; `h += v*dt`; `maxH = max(maxH, h)`.
  - if `stillDur ≥ anchorStill`: `v = 0`, `hadAnchor = true`, `anchorTime = t`, `anchorH = h` (updated every still sample).
  - end checks, in order (end ⇒ emit `.liftEnded(homingTime, endTime, reason)`, go `cooldown`, `cooldownUntil = t + cooldown`):
    1. `hadAnchor && anchorH - h > dropDistance` → endTime = `anchorTime`, `.drop`
    2. `hadAnchor && stillDur ≥ returnStill && |h| < returnHeight && t - liftStart > 1.0` → endTime = `t`, `.returned`
    3. `!hadAnchor && t - liftStart > noAnchorTimeout` → endTime = `t`, `.timeout`
    4. `t - liftStart > maxLiftDuration` → endTime = `hadAnchor ? anchorTime : t`, `.timeout`
- **cooldown**: when `t ≥ cooldownUntil` → `idle` (reset stillDur = 0, v = 0).

Clean & jerk works naturally: the front-rack hold is an anchor, the jerk's dip is far smaller
than `dropDistance`, and the lift ends at the overhead hold before the drop.

### Watch snippet extraction

On `.liftEnded(homing, end, reason)`, wait until the motion ring buffer's `latestTime ≥ end + postRoll`
(checked on each incoming batch), then cut `[homing - preRoll, end + postRoll]` from both
ring buffers (`preRoll = 2.0 s`, `postRoll = 1.0 s`), build the recording with
`SnippetBuilder`, write `<id>.json` to the watch's temp directory, `transferFile` it with
metadata `["type": "lift", "id": <uuid string>]`.

### Sign convention (revised after simulation review)

CoreMotion reports raw = gravity + userAcceleration (g units, gravity vector points down).
A physical accelerometer reads |raw| ≈ 1 + a_up/G, so `userAccel · ghat ≈ a_up / G`, i.e.
**userAcceleration = −(physical acceleration)/G**. Hence `aUp = +(userAccel·ghat)·G` and
world acceleration `aW = −rot(userAccel)·G`. The simulator generates data in this convention.

## 5. Offline analyzer (phone; precise)

> **Revision A (release index).** The forward EMA lags: it still says "still" for 50–130 ms
> after motion starts, and starting integration there loses real velocity (2–7 cm of height,
> always downward). Also run the same EMA *backward* in time (i from n−1 down to 0,
> `dt_i = clamp(t[i+1] − t[i], 0, 0.05)`, EMAs start at 0, same thresholds) → mask `stillB`.
> For each still run [r0, r1] (from the forward mask), `release = max{ i ∈ [r0, r1] : stillB[i] }`,
> or r0 if none. Everywhere below that says "last sample of the run", use `release` instead
> (homing index and homing velocity test start; motion segment start after an anchor;
> drop-test tail start; path end when a drop is found). Velocity is forced to 0 on
> [r0, release]. Run detection, durations and anchor qualification use the forward mask;
> anchors must start after the homing run's r1.


Input: one `LiftRecording`. Steps:

1. **World frame.** `aDev = -userAccel * G` (physical acceleration, see §4 sign note). CoreMotion's quaternion convention is easy to get
   backwards, so **auto-detect** it: compute `zA = median_i q_i.rotate(gravity_i).z` and
   `zB = median_i q_i.conjugate.rotate(gravity_i).z`. Use the variant whose value is closer to
   −1 (gravity points down in the world frame). If neither is below −0.8, fall back to
   *gravity-only* mode: vertical = `-(aDev · ghat)` (= `+(userAccel·ghat)·G`), horizontal = 0, add note
   `"Orientation unavailable: vertical only"`. World acceleration `aW_i = rot_i(aDev_i)`,
   with world z up.
2. **Stillness mask** using the same EMA formulas as §4 (`emaTau`, `stillRot`, `stillAcc`), run forward.
3. **Homing.** Find still runs (maximal runs of `isStill`). For each run with duration ≥
   `homingMinStill` (0.2 s), in time order: integrate vertical velocity from the run's last
   sample; if it reaches `startVelocity` (0.5 m/s) within `startWindow` (1.0 s) → homing index
   = last sample of that run. Take the first such run. If none, use `recording.homingTime`
   (nearest sample) if present, else throw `.noHomingFound`. Require ≥ 0.5 s of data after
   homing, else `.tooShort`.
4. **Anchors.** Still runs after homing with duration ≥ `anchorMinStill` (0.25 s). Velocity
   is forced to 0 inside anchor runs.
5. **Piecewise integration with drift removal (ZUPT).** For each motion segment
   `[s, e]` from the last sample of one still run (homing run or anchor) to the first sample of
   the next anchor run: `vRaw(i) = Σ_{k=s+1..i} ½(aW_k + aW_{k-1}) dt_k` (trapezoid, per axis);
   `drift = vRaw(e)`; `v(i) = vRaw(i) - drift * (t_i - t_s)/(t_e - t_s)`.
   `driftCorrection = |drift|` (3-D norm).
6. **Path end.** Walk the anchors in order, integrating positions (trapezoid on v, 0 at
   homing). If the motion after an anchor run falls more than `dropDistance` (0.5 m) below
   that anchor's height (integrate the open-ended tail with no drift removal for this test),
   the path ends at the **last sample of that anchor run**. If no drop is found, the path ends
   at the last sample of the last anchor run. If there's no anchor at all: integrate without
   correction for at most 3 s after homing, confidence `.low`, note `"No still recovery found:
   path uncorrected"`.
7. **Horizontal axes.** At homing, the watch face (device +z) points away from the lifter
   (watch on the back of the wrist, overhand grip, arm hanging). `f = rot_h(Vec3(0,0,1))`
   averaged over the homing still run, projected to horizontal (z = 0). If its horizontal norm
   ≥ 0.3 → `forwardAxis = f.normalized`. Else: PCA of the horizontal positions over the path
   (principal eigenvector of the 2×2 covariance), sign chosen so `maxForward ≥ |maxBackward|`,
   note `"Forward direction estimated"`. `lateralAxis = up × forwardAxis` with up = (0,0,1).
8. **Metrics** (§3 `LiftMetrics`): peak vertical velocity and time; `maxHeight` = max vertical
   between homing and the first anchor run that starts *after* the peak-velocity time (or path
   end); `catchHeight` = min vertical between the maxHeight sample and the start of that anchor
   run (nil if no such anchor); `dropUnderBar = maxHeight - catchHeight`; `finalHeight` = vertical
   at path end; `maxForward`/`maxBackward` = max/min forward over the path; `duration`.
9. **Segments**: one `LiftSegment` per motion segment within the path.
10. **Confidence**: `maxDrift = max driftCorrection`: `< 0.25 → .high`, `< 0.6 → .medium`,
    else `.low`. Gravity-only mode or no-anchor ⇒ at most `.medium` / `.low` respectively.

`AnalyzerConfig` fields: `emaTau, stillRot, stillAcc, homingMinStill, startVelocity,
startWindow, anchorMinStill, dropDistance, maxUncorrectedDuration (3.0)`.

  optional load (Digital Crown, kg), toggle "Record full session (debug)", big **Start** button.
- **Session screen** (`TimelineView` for elapsed time):
  - big status: idle → "Walk to the bar"; armed → "Ready" (green); lifting → "Lifting…";

- **MotionRecorder** (`@MainActor`): `CMBatchedSensorManager` accelerometer + deviceMotion

  Falls back to `CMMotionManager` device motion at 100 Hz if batched isn't supported
  (no accel stream then).
- **PhoneLink**: the **single** `WCSessionDelegate` in the app (one shared instance).
  `transferFile` for lifts and the debug CSV. Optionally `sendMessage(["type":"status",...])`

  `WKApplication = YES`, `WKCompanionAppBundleIdentifier`. Entitlement: HealthKit.

## 8. iPhone app (iOS 17+)

## 9. Known limitations (v1, documented in the app)

- Wrist ≠ bar center: a few cm of offset; no lever-arm correction yet.
- Forward direction assumes the watch is on the back of the wrist.
- Horizontal path is lower confidence than vertical.
- Standing up from the set without pulling the bar may produce a small false "lift".

## Revision C (after the first real recordings, 2026-10-27)

Real broomstick lifts showed lifters rarely hold the finish perfectly still (overhead wobble
≈ 0.1 g ≥ `stillAcc`), so the lift never got a closing anchor, the watch cut it after
`noAnchorTimeout` and the path was integrated uncorrected (≈ 0.5–1 m of drift). Changes, in
both Python and Swift:

- **Arms-down end (detector and analyzer).** `hang = s · ĝ.x` with `s = sign(ĝ.x)` at homing
  (≈ +1 arm hanging, ≈ −1 overhead). Once `hang < armsUpMax (0.3)` after homing (turnover),
  the first sample with `hang > armsDownMin (0.8)` means the bar was dropped/lowered.
  Detector: end the lift there (`.drop`, endTime = that t), checked before the other end rules.
  Analyzer: discard anchors starting at/after it; the path ends at the last anchor before it.
- **Pseudo-anchor (analyzer).** If no anchor starts after the turnover, take the calmest
  sample (min of a 0.1 s box-average of `|userAccel| + 0.05·|rotationRate|`) in the last 1.0 s
  before arms-down as a zero-velocity point; note "No still hold at the finish: end estimated
  at the calmest point before the drop".
- `noAnchorTimeout` 4 s → 8 s (fallback only).
- Confirmed on hardware: `corr(|raw| − 1, userAccel·ĝ) ≈ +0.7…0.9`, i.e. the physical sign
  convention of §4 is right. Arm hanging reads ĝ.x ≈ −0.95 on a Series 12 (left wrist).

## Revision D (after the calibration session and an independent review, 2026-10-27)

- **Kinematic pull / catch / lockout.** `maxHeight` is now the *pull height*: the highest point
  up to the first sample after peak vertical velocity where `vVertical ≤ 0`. `catchHeight` is
  the lowest point from there until `vVertical > catchRiseVelocity (0.15 m/s)` (the stand-up has
  begun) or the path end; nil only if the bar never stops rising. `dropUnderBar = pull − catch`;
  `finalHeight` is the lockout. No still pause in the catch is needed any more.
- **Sagittal-plane check.** If the sideways excursion `max |lateral| > maxLateral (0.15 m)`
  (not in gravity-only mode), add the note "Large sideways drift: horizontal path unreliable"
  and cap confidence at medium.
- The phone labels the chart "Wrist path" (it is the watch's path; bar = wrist + lever-arm
  offset, which isn't modelled yet) and shows Pull / Catch / Lockout heights.
- Review findings (see the calibration README): vertical ≈ ±2 cm on the snatch rise; the
  horizontal error is a repeatable dynamic velocity error during the fast phase (not static
  bias, not attitude), sensitive to accel–attitude timing (fused userAcceleration = raw 800 Hz
  delayed ~15 ms); where the ZUPT drift is placed changes the catch position by 1–11 cm.
  Next candidates: lever-arm (wrist → bar) offset calibrated from known bar heights,
  validated accel/attitude lag, energy-weighted drift placement — all need video ground truth.

## Revision E (validated against video bar paths, 2026-10-29 gym session)

Ground truth: plate-centre tracking on side-view videos (`data/raw/2026-10-29-gym/video_paths/`,
`tools/video_tracking/`), compared with `tools/compare_video.py`. Changes (Python + Swift):

- **Wrist → bar lever arm.** Path POSITIONS are the bar's: `bar = watch + R(t)·r − R(homing)·r`,
  `r = (s·leverForearm, 0, leverNormal)` in the device frame, `s = sign(ĝ.x)` at homing (toward the
  hand), `leverForearm = 0.109 m`, `leverNormal = −0.026 m` (fitted on 14 lifts). Velocities stay
  the wrist's (adding d/dt(R·r) overestimated peak velocity by 0.3–0.5 m/s vs video).
- **Drift placement.** Each ZUPT segment's drift is distributed proportionally to ∫|a_world| dt
  (`driftWeighting = accel`) instead of linearly in time: the error is made in the violent phases.
- **Pseudo-anchor for cleans (`pseudoAnchorMode = auto`).** For clean / powerClean / hangClean the
  pseudo-anchor only ENDS the path; the last segment is integrated without forcing v = 0, because
  the wrist keeps moving (elbows up) while the bar rests in the front rack. Snatches and C&J keep
  the zero-velocity pseudo-anchor.
- **End-over-start horizontal prior (`endOverStart = true`).** Forward and lateral get a linearly
  growing velocity correction so the bar finishes above the start; note "Forward/back estimated:
  assumes the bar finishes above where it started".
- Detector `noAnchorTimeout` 8 s → 15 s, so a clean & jerk's rack pause doesn't end the lift
  before the jerk (the arms-down rule still ends normal lifts at the drop).
- `AnalyzerConfig.wristReference` (Python: `WRIST_REFERENCE`) reproduces Revision D on the wrist,
  for the simulator ground-truth tests. Real-lift parity fixtures (`real_snatch`,
  `real_power_clean` + `.python.json`) pin Swift to the Python reference.

Accuracy vs video (median of aligned lifts): snatch vertical RMS 3–6 cm (was 10–23), horizontal
3–9 cm (was 24–30); power clean vertical 4–11 cm (was up to 81 cm short), horizontal 3–11 cm;
peak vertical velocity within ~0.1 m/s. Remaining misses: lifts that really finish away from the
start (e.g. jumping forward into the catch) and clean & jerks recorded with the old 8 s timeout.
